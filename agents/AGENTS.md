# AGENTS.md

## 基本原则

以**代码可维护性、正确性和整洁性**为第一优先级。项目仍处于 active development，不为未经要求的反向兼容增加补丁。

1. **保护现有工作**

   * 不覆盖、删除、回退用户未要求修改的内容。
   * 执行 reset、删文件、改历史、批量替换等破坏性操作前，必须取得明确确认。

2. **不确定时先确认**

   * 需求含糊、存在多种合理实现或涉及架构取舍时，先确认再修改。
   * 不基于未经验证的假设进行大范围或不可逆改动。

3. **修改前先阅读**

   * 修改文件前先阅读当前内容、调用方、依赖和已有实现模式。
   * 不根据文件名、记忆或猜测直接编辑。

4. **先定位根因**

   * 遇到错误时先检查报错、日志和调用链。
   * 形成明确的根因判断后，再进行最小化修复。
   * 不采用 guess-and-patch。

5. **只修改任务需要的内容**

   * 不在任务范围外重构、重命名、重新排版或顺手优化。
   * 必要的关联修改需要说明原因。

6. **保持实现简单**

   * 不增加无必要的 fallback、防御式分支或抽象层。
   * 简单逻辑不拆成大量函数或类。
   * 只在真实扩展点使用接口、工厂或适配器。

## 依赖管理

* 使用 `uv` 管理 Python 环境和项目依赖。
* 项目依赖写入 `pyproject.toml`，并提交 `uv.lock`。
* Isaac Sim、Isaac Lab、Newton 等依赖必须固定到明确版本或 commit。
* Isaac Lab 通过项目环境安装，不使用 git submodule。
* 不使用未固定的 `main`、`develop` 或 `latest` 依赖。
* 不修改 `.venv`、`site-packages` 或第三方依赖源码。
* 不使用 monkeypatch 绕过第三方依赖问题。
* 需要上游修改时，应记录限制并提交 upstream issue 或 PR。

## 配置与运行

* 运行参数优先通过配置文件管理，CLI 参数可以覆盖配置。
* 不在代码中写死路径、设备编号、GPU 型号或本地环境信息。
* 密钥、`.env`、下载资产、生成视频和其他大文件不得提交到 Git。
* 不在模块 import 时启动仿真、下载文件或写入磁盘。
* CLI 必须使用显式入口，例如 `main()`。

## 编码规范

* 使用 ASCII 和 4 空格缩进。
* 类名使用 `CamelCase`。
* 文件、函数和变量使用 `snake_case`。
* 常量使用 `UPPER_SNAKE_CASE`。
* 文件路径使用 `pathlib.Path`。
* 公开接口和阶段间数据结构应提供类型标注。
* 随机行为必须使用显式 seed 或传入的 RNG。
* 不使用隐式全局状态。
* 优先复用项目已有模式和依赖，不为单一需求引入新框架。

## 修改约束

* 不修改任务无关文件。
* 不改变公开接口、配置结构或输出格式，除非任务明确要求。
* 不静默修改输入配置或中间数据。
* 如果运行阶段需要修正配置，应输出明确的 resolved 配置并保留原配置。
* 外部数据、原始资产和模板默认视为只读。

## 文档同步

以下修改必须同步更新相关文档：

* CLI 命令；
* 配置字段；
* 目录结构；
* 安装流程；
* 依赖版本；
* 运行工作流；
* 输入输出格式；
* 公开接口或扩展点。

README 面向用户说明使用方式；`AGENTS.md` 记录开发和修改规范。

## 验证要求

修改完成后，应运行当前环境中可执行的检查，例如：

```bash
uv run --no-sync python -m compileall .
uv run --no-sync pytest
uv run --no-sync ruff check .
```

涉及 Isaac Sim、Isaac Lab 或 Newton 时，根据任务运行对应的 import 或 smoke test。

验证报告必须明确说明：

* 实际执行的命令；
* 通过的检查；
* 失败的检查；
* 未执行的检查及原因；
* 需要用户执行的人工验证步骤。

不得在未执行测试的情况下声称已经验证。

## 事实与错误处理

* 不编造 API、配置项、命令、测试结果或外部行为。
* 对不确定的信息，先查阅当前依赖源码或官方文档。
* 无法验证时应明确说明限制。
* 错误应提供明确上下文，不静默忽略或错误降级。
